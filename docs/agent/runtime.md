# AI 角色统一事件运行时

AI 角色统一事件运行时（Unified Event Runtime）通过 `AgentRuntime` 统一宿主入口，并使用 `AgentRunner` 和 Pi 工具决策循环，将玩家实时聊天、定时任务计划触发、异步动作执行反馈等所有外部输入归一化为标准的内部事件流。

```mermaid
flowchart TD
  Chat[玩家聊天 / 私聊 / 语音转写] --> Inbox[角色事件收件箱 (Event Inbox)]
  Plans[TaskPlan 定时计划到期] --> Queue[排队中的 TaskRun]
  Queue -->|前序任务结束或空闲| Inbox
  Controls[控制台 / 玩家打断指令] --> Cancel[鉴权后立即取消活跃动作]
  Cancel --> Inbox
  Inbox --> Runner[AgentRuntime / AgentRunner 统一执行入口]
  Runner --> Policy[TaskService 归属与权限校验]
  Runner --> Actions[动作执行器: goto / build / house / follow]
  Actions -->|物理执行确认或阻碍| Inbox
  Runner --> Reply[按会话范围定向回复]
  Runner --> Save[事件 / 检查点原子持久化]
```

服务端与 CLI 共用 `createAgentRuntime()` 门面。消息接入、任务控制、状态视图和重启恢复由运行时提供；计划账本、世界连接与联合存档提交由宿主负责。保存的 v3 状态格式和既有入口保持兼容。

## 事件流与执行机制

### 1. 单槽执行与模型会话复用

每个 AI 角色在运行时内拥有且仅拥有一个**模型执行槽**：

- **会话持久化**：角色状态与会话历史由运行时持续保存；每次决策装配 Pi Agent 并回放对应历史；
- **上下文热切换**：处理不同事件时，系统动态装配并注入当前事件对应的授权范围与消息历史；
- **排队与调度**：同一时间仅允许一条任务处于活跃执行态（Active TaskRun），周期任务在未空闲时进入排队状态（Queued）。

### 2. 事件收件箱与审计

- **唯一去重标识**：所有事件均包含全局唯一的去重 ID、事件类别、会话范围及触发者身份；
- **内存与持久化**：玩家消息先写入持久化存储后再推送至内存处理队列；
- **历史审计窗口**：内存中保留待处理事件以及最近 64 条已处理事件审计记录。

## 上下文管理与私密隔离

### 1. 结构化任务进度与对话隔离

- **独立上下文堆栈**：公共广播聊天与不同玩家的独立私聊会话严格物理隔离；
- **窗口保护**：公共交流以及每个私聊会话分别维护最近 8 组完整的交互上下文（包含用户输入与工具回执），上限追踪 16 个私聊对象；
- **私密保护**：私聊指派的任务，其详细施工进度、检查点与汇报文本仅向发起玩家可见，公共广播无法窃听其执行细节。

### 2. 意图转换与任务修订

- **日常问答**：询问进度或日常交流调用 `reply` 工具，不打断或重置已有任务；
- **任务目标调整**：收到修订指令时调用 `revise_task`，保持角色身份、累计已消耗额度与施工蓝图连续性；
- **任务切换**：切换到全新目标时，系统先安全停止旧动作物理线程，再初始化新任务，角色累计消耗正常累加。

## 持续异步长动作 (Continuous Actions)

对于需要跨多个时钟周期完成的复杂动作（如远距离导航、多层房屋建造），运行时采用了异步动作句柄机制：

| 动作类型 | 内部推进方式                                  | 中断与恢复表现                                       |
| -------- | --------------------------------------------- | ---------------------------------------------------- |
| `build`  | 批次内约每 125ms 推进一块方块校验             | 遇到障碍或超出距离立即返回未完成蓝图；暂停时保留进度 |
| `house`  | 解析为地板、墙体、门洞等分层方块批次          | 发现异物方块立即暂停并报告障碍，不破坏已有地形       |
| `goto`   | 本地 A\* 寻路并在 10Hz 下持续发送物理移动包   | 支持绕行与攀爬；中途环境改变支持有限次数重新规划     |
| `follow` | 监听目标玩家位置，动态跟随并维持 0.8–4 格间距 | 超出距离自动推进，不额外消耗模型调用 Token           |

::: tip 动作与消息并行
在持续长动作执行期间，Agent 仍可在动作边界及时响应玩家的日常对话消息，而无需打断正在进行的物理位移或建筑施工。
:::

## 资源额度与预算保护

为了杜绝自动化循环死锁与不可控的 API 费用，系统内置了多层预算防护：

| 保护指标                              | 默认限额 |      可调最大上限      | 机制说明                               |
| ------------------------------------- | :------: | :--------------------: | -------------------------------------- |
| **单任务调用轮次 (`maxTurns`)**       |  100 次  |        1,000 次        | 防止模型陷入多轮无效循环               |
| **单任务 Token 预算 (`tokenBudget`)** |  50,000  |      100,000,000       | 控制单次 TaskRun 的最大 Token 消耗     |
| **有效执行超时 (`taskTimeoutMs`)**    | 15 分钟  | 6 小时 (21,600,000 ms) | 仅统计模型推理与动作实际推进的活跃耗时 |
| **重复计划累计总额度**                | 500,000  |     1,000,000,000      | 针对多次周期重复执行的总预算封顶       |

- **执行限制开关**：角色表单中可由管理员自主勾选开启或解除上述额度限制；
- **额度耗尽表现**：达到上限后任务安全转为“已暂停”，控制台将清晰标注超限原因，并允许管理员人工追加预算后继续推进。

## 持久化、检查点与故障恢复

1. **版本化存档**：聚合存档数据规范为 v3 协议，Pi 检查点为 v3，事件队列为 v1；
2. **原子文件写入**：每次存档更新均经过临时文件写入与原子替换（Atomic Rename），彻底防止异常宕机导致文件损坏；
3. **断电重启自愈**：
   - 服务重启后，正在执行的任务自动转为“已暂停（Paused）”；
   - 处于执行中途的未知动作标记为 `unknown`，杜绝未确认动作产生副作用重放；
   - 角色自动上线并进入待命状态，等待新事件唤醒或人工恢复任务。
