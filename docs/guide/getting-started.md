# 快速开始

本指南将指导您在本地快速搭建、启动并体验 Agent Voxel World，包括本地裸机开发与 Docker 一键全栈容器化部署两种方式。

::: tip 核心技术要求

- **Node.js**：`v22.13+`
- **包管理器**：`pnpm v10+`
- **数据库**：PostgreSQL 17（支持本地独立进程或 Docker 卷挂载）
  :::

---

## 本地裸机极速开发

通过项目内置的本地数据库启停脚本，无需安装 Docker 即可在本地完整运行全栈世界。

### 1. 依赖安装与数据库初始化

本地开发与 Docker 部署统一使用根目录的 `.env.example`。首次配置时复制为 `.env`；已有 `.env` 可按示例补充所需选项。

```bash
# 首次配置（保留已有 .env）
cp -n .env.example .env

# 1. 冻结锁文件严格安装依赖
pnpm install --frozen-lockfile

# 2. 生成 Prisma ORM 客户端
pnpm db:generate

# 3. 启动项目专有本地 PostgreSQL 17 实例（端口 55432）
pnpm db:start

# 4. 执行数据库架构迁移
pnpm db:migrate
```

::: info 本地数据库隔离机制
`pnpm db:start` 仅在当前项目的 `.data/postgres` 目录中初始化一个沙箱数据库，默认监听 `127.0.0.1:55432`，并自动生成被 Git 忽略的 `.env` 配置文件（绝不覆盖已存在的 `.env`）。

- **停止数据库**：`pnpm db:stop`
- **重启复用数据**：再次执行 `pnpm db:start` 即可，只要不删除 `.data` 目录，所有世界方块与 Agent 数据均持久保留。
  :::

### 2. 启动服务与进入世界

在一个终端窗口中启动 Web 前端与 Colyseus 游戏服务端：

```bash
pnpm dev
```

在另一个终端中，可选择启动常驻的 AI 玩家或测试机器人进入世界协作：

```bash
# 启动智能 AI 代理（更多命令行参数见 Agent 玩家文档）
pnpm agent:ai --api-key sk-your-deepseek-api-key

# 或启动仅进行随机行为测试的 Mock 机器人
pnpm agent:mock
```

- **访问世界**：在浏览器打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。
- **多人联调**：建议使用两个独立的浏览器窗口（或一个普通标签页、一个无痕标签页）输入不同昵称加入，即可在 49×49 的体素世界中实时看到彼此。

### 3. 启动故障与常见排错

| 异常现象 / 错误提示                        | 根本原因分析                     | 快速解决方案                                                |
| :----------------------------------------- | :------------------------------- | :---------------------------------------------------------- |
| **`connect ECONNREFUSED 127.0.0.1:55432`** | 本地沙箱 PostgreSQL 尚未启动     | 运行 `pnpm db:start` 检查数据库状态，随后重启 `pnpm dev`。  |
| **提示表结构未准备好 (`Table not found`)** | 数据库连接正常，但未执行迁移脚本 | 终端运行 `pnpm db:migrate` 同步数据表。                     |
| **控制台黄色警告：`memory 模式`**          | 未配置有效的 `DATABASE_URL`      | 若需持久化，运行 `pnpm db:start` 并在 `.env` 中确认连接串。 |
| **Vite 显示 Ready 但无法连接世界**         | 后端服务尚未完全就绪             | 检查后端终端日志，服务需成功连接数据库后才开放 2567 端口。  |

## Docker 全栈一键部署

项目提供生产就绪的 Docker Compose 编排配置，整合了 Nginx 前端反代、Node.js 游戏服务端、PostgreSQL 17 以及 Speaches 语音容器。

### 1. 架构与端口映射

```
                                  [ 用户浏览器 ]
                                        │
                                        ▼ (80 端口)
                             ┌─────────────────────┐
                             │    Nginx (Web 前端)  │
                             └──────────┬──────────┘
                                        │ /api, /world, Colyseus WS
                                        ▼ (2567 端口)
                             ┌─────────────────────┐
                             │  Node.js 权威服务端  │
                             └──┬────────────────┬─┘
                  SQL 查询 (55432)│                │ ASR / TTS 推理 (8000)
                                ▼                ▼
                      ┌──────────────────┐  ┌──────────────────┐
                      │ PostgreSQL 17 DB │  │ Speaches 语音容器 │
                      └──────────────────┘  └──────────────────┘
```

### 2. 一键启动指令

首次部署时使用同一份 `.env.example`，按需修改其中的 Docker Compose 配置区，设置数据库密码与对外端口。

```bash
# 首次配置（保留已有 .env）
cp -n .env.example .env

# 使用 pnpm 快捷脚本一键构建并后台启动
pnpm docker:up

# 或直接使用 Docker Compose 原生指令
docker compose up -d --build
```

启动完成后各服务入口如下：

- **Web 游戏与管理界面**：`http://localhost`（默认 80 端口，前端通过 Nginx 统一反代 WebSocket）
- **Swagger 交互式 API 文档**：`http://localhost:2567/api-docs`
- **本地 PostgreSQL 实例**：宿主机暴露 `55432` 端口，数据持久化于 `voxel_postgres_data` 卷。
- **Speaches 语音推理服务**：容器内 `8000` 端口，包含离线 Whisper 识别与 Piper 语音合成。

### 3. 常用运维命令

```bash
# 查看实时全栈服务输出日志
pnpm docker:logs

# 安全停止并保留所有数据卷
pnpm docker:down

# 停止并彻底销毁所有数据卷（注意：将彻底清空世界数据与已下载模型缓存）
docker compose down -v
```

### 4. 关键环境变量配置清单

参考根目录 `.env.example` 的通用配置和 Docker Compose 配置区（模型凭据及 Agent 行为在 Web 控制台配置）。`WEB_ORIGIN` 和语音服务地址默认保持注释：本地运行使用本机地址，Compose 使用容器网络地址和自己的跨域默认值；需要覆盖时填写服务器所在环境可访问的地址。

示例中的 `DATABASE_URL`、`HOST`、`PORT` 用于本地运行。Compose 使用 `POSTGRES_USER`、`POSTGRES_PASSWORD`、`POSTGRES_DB` 生成容器内数据库连接串，并固定容器监听地址和端口。调整宿主机端口请使用 `WEB_PORT`、`SERVER_PORT`、`POSTGRES_PORT`、`SPEECH_PORT`。

| 环境变量         | 默认值                  | 作用说明                                   |
| :--------------- | :---------------------- | :----------------------------------------- |
| `WEB_PORT`       | `80`                    | Web 界面宿主机对外访问端口                 |
| `WEB_ORIGIN`     | `*`                     | 生产环境下建议配置为严格的前端域名         |
| `SPEECH_API_URL` | `http://speech:8000/v1` | 指向全栈编排内的语音识别与合成统一服务入口 |
| `DATABASE_URL`   | 容器内部网络连接串      | 自动注入，无需手动修改                     |

## 世界交互与操作指南

进入体素世界后的标准交互按键如下：

| 交互维度         | 操作快捷键           | 详细行为说明                                                 |
| :--------------- | :------------------- | :----------------------------------------------------------- |
| **视角控制**     | 鼠标点击画面 / `Esc` | 点击画面锁定鼠标进入第一人称视角；按 `Esc` 释放鼠标指针。    |
| **角色移动**     | `W` `A` `S` `D`      | 基础四向位移，服务端以 20Hz 执行碰撞与重力模拟。             |
| **跳跃起跳**     | `Space`（空格键）    | 在地面时起跳，最高可跃过 1 格高度的体素方块。                |
| **破坏方块**     | 准星对准 + 鼠标左键  | 在 6 格有效交互距离内破坏目标方块（基岩不可破坏）。          |
| **放置方块**     | 准星对准 + 鼠标右键  | 在目标表面放置选定材质的方块（支持草地、泥土、石块、木头）。 |
| **材质切换**     | 画面底部快捷栏       | 点击选中所需材质，或点击底部 `Remove / Place` 辅助按键。     |
| **多模态社交**   | 右下角控制台         | 支持文字聊天、定向私信、长语音听写以及语音留言。             |
| **空间语音对讲** | 右上角语音面板       | 开启麦克风与他人进行具备 3D 距离衰减的真实 WebRTC 对讲。     |

::: info 权威物理校验
所有方块破坏与放置均在服务端进行距离校验、相邻支撑结构校验、玩家包围盒碰撞检测以及版本并发锁判定，客户端严禁越权伪造。
:::

## 接入首个 AI 玩家

1. 打开游戏控制台或直接访问管理员面板。
2. 输入管理员访问令牌（本地可通过 `pnpm agent:ctl auth show` 查询当前令牌）。
3. 进入 **Agent 玩家 → 创建 Agent**：
   - 设定角色昵称与角色系统提示词；
   - 选择预设的 LLM 思考模型服务（如 DeepSeek）；
   - 配置自主发音音色（如 Piper 华岩或百炼 Qwen-TTS）；
   - 配置执行配额（最大步数、工具调用深度）。
4. 保存后点击 **加入世界**，Agent 将立刻化身 3D 体素角色空降世界并待命！

进一步深入了解请参阅 [AI 玩家接入与控制台指南](/agent/players.md)。
